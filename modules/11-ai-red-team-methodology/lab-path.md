# Module 11 Lab Path: AI Red Team Methodology

## Role in the 40-hour course

Module 11 uses BrokenPilot for an observable attack-chain path and uses tabletop exercises for scoping, rules of engagement, reporting, and stakeholder communication.

## Runnable path

- BrokenPilot attack-chain lab
- BrokenPilot standalone Module 11 lab
- Finding rewrite exercise based on BrokenPilot evidence

## Reasoning path

- AI red-team scoping tabletop
- Rules of engagement and test-plan quality review

## Suggested practice deliverable

A red-team finding or scope package with evidence, root cause, impact, control, validation, residual risk, and clear leadership summary.

## Keep central

- Evidence quality over bug count
- Scope, safety, and authorization are part of the assessment

## Avoid

- Do not let students treat red teaming as unbounded poking
- Do not treat novelty or exploit count as the whole learning outcome

## Instructor note

Use this file as the first stop when deciding what to run live and what to offer for self-study. If a lab cannot produce observable vulnerable and controlled behavior, treat it as a reasoning exercise with a written artifact instead of pretending it is runnable. Rubrics are optional feedback guidance.
