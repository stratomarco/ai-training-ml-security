# Module 12 - BrokenPilot Capstone

## Purpose

Turn the evidence collected in Modules 05, 06, 07, 09, and 11 into a security decision for the owner of BrokenPilot. The runnable app covers direct and indirect prompt injection, retrieval authorization, output handling, ticket-tool authorization and approval, and memory poisoning. Use the separate toy classifier and MLOps evidence pack for their own topics; do not describe those as BrokenPilot exploits.

## Student path

1. Read the [student reading guide](student-reading-guide.md) and [student handout](student-handout.md).
2. Follow the [capstone checkpoints](capstone-checkpoints.md) and [lab path](lab-path.md).
3. Use the [threat-model exercise](exercise-capstone-threat-model.md) to identify assets, boundaries, personas, and abuse cases.
4. Run the [red-team review](exercise-capstone-red-team-review.md) against the local prototype. Label paper-design risks as tabletop analysis.
5. Write the report using the [current final-report path](final-report-current-path.md). Compare the result with the worked example only after drafting your own findings.

## Deliverable

Produce a final report with an executive recommendation, scope, at least four evidence-backed findings, a remediation backlog, validation steps, and residual risk. Prepare a short readout that lets the system owner decide what must change before a broader pilot. Rubrics and the [quiz](quiz.md) are optional feedback tools.

For the module's place in the full course, see the [cohesion note](cohesion-note.md).
