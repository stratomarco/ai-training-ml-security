# AIGoat adoption evaluation

Status: **two MCP exercises and a contained Windows setup passed on one maintainer host, including an isolated fresh-state replay; independent learner and other-platform pilots remain open**. This is an instructor planning note. BrokenPilot remains the primary local LLM, RAG, agent, and capstone target. The current 40-hour path does not require AIGoat.

## Why consider it

[AIGoat](https://github.com/AISecurityConsortium/AIGoat) by AISecurityConsortium has a separate tool-using agent and MCP client/host with local models. Its [v2.0 release](https://github.com/AISecurityConsortium/AIGoat/releases/tag/v2.0) describes 46 labs across LLM, agent, and MCP surfaces. The clearest addition to this course is **MCP-specific trust boundaries** that BrokenPilot does not implement. More prompt-injection examples alone would duplicate our current path.

Use a separately downloaded upstream release for any pilot. Do not vendor its application, prompts, lab definitions, walkthroughs, images, or branding into this repository. AIGoat is maintained by AISecurityConsortium; this course is independent and has no stated endorsement from them.

## Safety and delivery gates

1. **Version and terms:** evaluate the `v2.0` release at commit `e1c538badb93c6c1c2307096ab5d709a9ee0fe55` first and record any dependency or license changes. The upstream `main` branch can change independently.
2. **Contained setup:** inspect startup scripts, Compose configuration, model pulls, executable tools, MCP server launchers, external dependencies, and service bindings before running. At v2.0, [`start.sh`](https://github.com/AISecurityConsortium/AIGoat/blob/v2.0/scripts/start.sh) starts the backend on `0.0.0.0`; [Docker Compose](https://github.com/AISecurityConsortium/AIGoat/blob/v2.0/docker/docker-compose.yml) publishes 3000, 8000, and 11434 on `0.0.0.0`. The app also ships known demo credentials. A course setup must bind every exposed service to loopback, use fake data, and verify actual listeners. Neither upstream start command should be handed to students as a safe default on a shared or public network.
3. **Capacity and support:** its documented local path needs Python 3.11, Node 18+, Ollama, and at least 8 GB free RAM. The two recommended MCP client exercises make local MCP calls without a live agent model. The Docker stack still starts Ollama and downloads a configured model; the backend build pulled large AI and CUDA dependencies. Confirm a repeatable Windows, macOS, and Linux route before promising cross-platform support. Do not treat Google Colab as the offline route.
4. **Teaching evidence:** repeat the MCP03-2 and MCP07-1 vulnerable and defended comparisons from a reset state, preserve tool listing/call/result evidence, and check that the stated control matches what happened. A model refusal is an observation, not proof that the application boundary held. Treat ASI07-1 as a discussion example until its signature semantics can be taught without implying authentication it does not provide.
5. **Learner pilot:** only after instructor smoke checks, ask a first-time learner whether setup and the chosen control comparison can be completed without coaching. Record the time and blockers. Keep it outside the required 40-hour path unless it teaches a distinct, repeatable outcome.

The two MCP exercises pass the teaching gate. A course launcher now passes the contained Windows instructor gate, with the full upstream media set, for just these two exercises. The [optional source review](../labs/aigoat-guides/mcp-trust-boundary-review.md) remains the no-install route and the [Windows setup](../labs/aigoat-guides/windows-mcp-setup.md) is a live-trace option. BrokenPilot remains the required path. Revisit broader integration only when a first-time learner can complete setup and the control comparison without coaching, and other supported platforms have been checked.

## Bounded instructor pilot, 15 October 2026

The v2.0 tag resolved to the commit above. The source was cloned into an Ubuntu WSL filesystem. A native Windows checkout failed because seven product-image filenames contain a double quote, which Windows cannot represent. For this pilot only, a separate Windows Docker build context omitted those seven images. The course repository contains no AIGoat source or media. This workaround has not been tested as a learner installation path, and those product images were not verified in the UI.

Docker Desktop built and ran the upstream frontend and backend in a separately named pilot stack. A pilot-specific Compose file bound ports 3000, 8000, and 11434 to `127.0.0.1`; the rendered Compose configuration, actual host listeners, frontend response, and backend response were checked. The backend initialized its database and pulled `tinyllama` because this pair of MCP exercises does not use a live agent model. The upstream Docker build installed unpinned or loosely bounded dependencies, including large CUDA packages, even for this CPU-based pilot. This is a material setup cost and a reproducibility issue. Loopback binding limits host exposure, but does not remove container egress or make an intentionally vulnerable app safe to deploy on a shared host.

| Lab and reset state | Vulnerable observation | Defended observation | Control actually tested |
|---|---|---|---|
| MCP03-2, Level 0 vs Level 1 | First `lookup_ticket` call returned public status. After a second tool listing, the same call executed and returned extra staff data marked as a training artifact. | First call executed normally. After the second listing, the second call was denied before server execution with a tool-description pin mismatch. | The client compared the live definition with its approved pin at call time. This lab makes real local MCP calls; it does not need a model decision. |
| MCP07-1, Level 0 vs Level 1 | Support diagnostics revealed a decoy catalog token; the catalog accepted that value for its mock staff-price tool. | Support diagnostics ran but reported that the catalog token was not provided. | The client scoped the launch environment. This is credential distribution, not output filtering. No production credential was used. |
| MCP03-1, Level 0 vs Level 2 | A simulated plan gained an unrequested internal-notes step. | Description inspection removed the instruction and the simulated plan matched the baseline. | A deterministic planner simulation only. No model or server tool executed in this comparison. |

The API control comparisons above passed on this one Windows and Docker Desktop host. They do not validate a first-time learner setup, other operating systems, the seven omitted images, or model-driven agent behavior. No pilot volunteer is available yet. The next gate is a fresh learner install with actual setup time, port checks, exercise completion, and teardown recorded. Stop the pilot stack when the session ends; do not leave vulnerable services running by default.

## Fresh student-style run, 15 October 2026

I cloned the pinned v2.0 commit into a fresh Ubuntu WSL filesystem and followed a learner setup path on one Windows machine with Docker Desktop. This is an accelerated maintainer-run walkthrough, not an independent volunteer pilot. A native Windows checkout still cannot represent seven upstream product-image filenames containing a double quote. Building the full WSL source through Docker Desktop avoids the checkout failure, but the upstream Compose bind mounts failed because Docker Desktop's Ubuntu WSL integration socket was unavailable. For this run I used a separate Compose file that bound all three published services to `127.0.0.1`, baked a fake local configuration into the backend image, omitted four failing backend bind mounts, disabled debug mode, and used a fresh randomly generated session secret. No course source or media was copied from AIGoat.

The stack became healthy with fresh database and model volumes and a local `tinyllama` model. I confirmed actual host listeners for ports 3000, 8000, and 11434 were loopback-only. In the browser I logged in with the upstream demo account and completed MCP03-2 Level 0 and Level 1 and MCP07-1 Level 0 and Level 1. Each case's vulnerable and defended result matched the separate API pilot, and the upstream UI accepted the evidence submissions. This confirms the two teaching comparisons are usable through the UI on this contained setup. It does not test a live agent model.

**Student-visible delivery defect:** Seven product images failed to load in the browser (`naturalWidth=0` and HTTP 404). The Docker build context lacked the quoted filenames even though the WSL checkout contained them. The two MCP exercises remained functional. A supported learner route needs this media issue resolved or explicitly removed from the delivered UI. It also needs a tested, documented setup on the target operating systems, predictable dependency and model-download requirements, and an independent first-time learner with timing and support notes. Until then, keep the course extension as credited source review with optional use of a separately contained upstream instance.

The fresh AIGoat stack was stopped after validation. No vulnerable service was left listening on those ports.

## Contained Windows MCP route, 16 October 2026

The course now provides a [Windows launcher and setup guide](../labs/aigoat-guides/windows-mcp-setup.md) for the two selected MCP labs. It calls Windows Docker Desktop from Ubuntu WSL, so Docker's Ubuntu integration socket is not required. It builds the exact pinned Git archive, preserving all seven filenames that native Windows cannot check out. The backend image built successfully; the upstream dependency installation was still large and loosely bounded. The launcher did not start Ollama or download a model. It generated a random local session secret in an ignored config file, disabled debug and RAG, and used a separate persistent database volume.

The first Compose attempt used only an internal network and did not publish the frontend port. A split network fixed that: the backend has only an internal network, while the static frontend also has a network for a `127.0.0.1:3000` host binding. The final stack passed a strict Compose render and health check. A one-shot, networkless container prepared ownership of the persistent volume, then the backend ran as UID 10001. Inspection confirmed the backend had no host port, a read-only root filesystem, all capabilities dropped, `no-new-privileges`, and no outbound connection to an external IP. The frontend and product API returned HTTP 200. All 34 media files in the pinned checkout appeared in the backend image and returned HTTP 200 through the frontend, including the seven previously missing images.

Fresh API comparisons passed MCP03-2 at Level 0 and Level 1 and MCP07-1 at Level 0 and Level 1, both before and after switching the backend to UID 10001. The observed differences matched the upstream integrity tests: a redefined tool returned extra training data at Level 0 and was denied before execution at Level 1; a decoy catalog token reached support diagnostics and worked against the mock staff-price tool at Level 0, while Level 1 withheld it. No token value was printed in the check. A stop and restart preserved the learner database user count, 9 before and 9 after. The launcher's default WSL clone path initially failed because the Windows shell did not preserve nested quoting; after replacing that call with direct WSL arguments, a new pinned clone started successfully. The stack was stopped after validation.

This removes the Windows media and Docker integration blockers for the selected optional labs on the tested host. The upstream backend image remains a substantial download and build, and its broad dependency ranges make future rebuilds less predictable. The setup has not been timed with an independent first-time student or validated on macOS or native Linux. Keep this outside the required 40-hour path until those gates are met.
